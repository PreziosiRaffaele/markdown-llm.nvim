*markdownllm.txt*  Markdown-based LLM chat for Neovim

==============================================================================
MarkdownLLM                                                     *markdownllm*

MarkdownLLM is a Neovim plugin that provides a markdown-driven interface for
interacting with LLM providers. It focuses on explicit, editable context inside
normal buffers rather than an opaque agent workflow.

==============================================================================
Installation                                                   *markdownllm-install*

Use your plugin manager and load the module in your config:
>
  require("markdownllm").setup({
    log_level = vim.log.levels.INFO,
    default_setup_name = "default",
    setups = {
      {
        name = "default",
        provider = "openai",
        model = "gpt-4o-mini",
        api_key_name = "OPENAI_API_KEY",
      },
    },
    presets = {
      { name = "Chat", instruction = "" },
    },
    actions = {},
    keymaps = {
      newChat = "<leader>mn",
      sendChat = "<leader>ms",
      selectChatSetup = "<leader>mc",
      selectDefaultSetup = "<leader>md",
      actions = "<leader>ma",
      saveChat = "<leader>mw",
      resumeChat = "<leader>mr",
    },
  })
<

==============================================================================
Commands                                                     *markdownllm-commands*

:MarkLLMNewChat
    Open a new chat buffer (optionally with a preset).

:MarkLLMSendChat
    Send the current chat buffer to the provider.

:MarkLLMRunAction
    Send the current visual selection using an action.

:MarkLLMSelectBufferSetup
    Set the setup for the current buffer.

:MarkLLMSelectDefaultSetup
    Set the default setup for new buffers.

:MarkLLMSaveChat
    Save the current chat buffer to disk.

:MarkLLMResumeChat
    Resume a saved chat from disk.

==============================================================================
Configuration                                                *markdownllm-config*

The setup table supports:

log_level
    Logger level (default: vim.log.levels.INFO).

log_to_file
    Enable logging to file (default: false).

log_file_path
    Log file path (default: stdpath("cache") .. "/markdownllm.log").

default_setup_name
    Name of the default setup used for new chats.

setups
    List of provider/model setups. Each setup is a table with:
      name          (string) unique label used in selectors.
      provider      (string) provider name: "openai", "gemini", "grok", "deepseek".
      model         (string) model id passed to the provider.
      api_key_name  (string) environment variable containing the API key.
      base_url      (string|nil) optional override for OpenAI-compatible endpoints.
      timeout       (number|nil) optional request timeout in milliseconds.
      temperature   (number|nil) model temperature.
      max_tokens    (number|nil) model max tokens.
      top_p         (number|nil) nucleus sampling.
      stop          (string|table|nil) stop sequence(s).
      frequency_penalty (number|nil) frequency penalty.
      presence_penalty  (number|nil) presence penalty.
      seed          (number|nil) sampling seed.
      web_search    (boolean|nil) enable provider web search tool when supported.

presets
    List of prompt presets used to seed new chats. Each preset is a table with:
      name         (string) label shown in the preset selector.
      instruction  (string|nil) content injected under the "# System" section.
      setup        (string|nil) setup name override; defaults to default_setup_name.

actions
    List of actions used for visual selection prompts. Each action is a table with:
      name      (string) label shown in the action selector.
      preset    (string|nil) preset name to open; defaults to first preset.
      type      (string|nil) "text" (default) or "code"; "code" wraps the
                selection in a fenced code block, "text" inserts raw text.
      language  (string|nil) optional code fence language when type = "code";
                defaults to the current buffer filetype when omitted.
      pre_text  (string|nil) text prepended before the selection.

chat_save_dir
    Directory for saved chats (default: stdpath("data") .. "/markdownllm/chats").

keymaps
    Optional command bindings.

Keymap fields:
    newChat
    sendChat
    selectChatSetup
    selectDefaultSetup
    actions
    saveChat
    resumeChat

==============================================================================
Chat Frontmatter                                     *markdownllm-frontmatter*

Each chat buffer begins with YAML frontmatter that mirrors the setup. Edit the
frontmatter directly to change providers or model options:
>
  ---
  provider: openai
  model: gpt-5.2
  api_key_name: OPENAI_API_KEY
  temperature: 0.2
  max_tokens: 800
  ---
<

==============================================================================
Providers                                                  *markdownllm-providers*

The following providers are currently supported:
  OpenAI-compatible (OpenAI, xAI, DeepSeek)
  Google (Gemini)

Other providers can be added per request. Raise an issue or PR to add a new provider.

==============================================================================
LLM Engine                                                     *markdownllm-llm*

`markdownllm.llm` exposes the low-level request API used by the plugin. You can
use it directly to send a completion request from Lua (for example, inside your
own plugin or command).

Usage:
>
  local llm = require("markdownllm.llm")

  local request = {
    context = {
      provider = "openai",
      model = "gpt-4o-mini",
      api_key_name = "OPENAI_API_KEY",
      stream = true,
      timeout = 30000, -- ms
    },
    messages = {
      { role = "system", content = "You are a concise assistant." },
      { role = "user", content = "Explain Lua metatables in one paragraph." },
    },
    options = {},
  }

  llm.send(request, {
    on_chunk = function(text)
      -- Streaming token(s) arrive here.
      vim.api.nvim_out_write(text)
    end,
    on_complete = function()
      vim.api.nvim_out_write("\n")
    end,
    on_warning = function(warn)
      vim.notify(warn, vim.log.levels.WARN)
    end,
    on_error = function(err)
      vim.notify(err, vim.log.levels.ERROR)
    end,
  })
<

`request.context` carries provider/model selection, API key name, optional
base_url/timeout, and a `stream` flag. `messages` is the standard list of
role/content pairs. `options` is passed through to the provider driver.
